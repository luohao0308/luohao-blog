# 评论作者回复

实现切片见[计划](../plans/SERIES-AUTHOR-REPLIES-2026-11.md)，是否已上线以TASKS为准。本文补充[小程序内容安全契约](WECHAT-CONTENT-SAFETY.md)，不改变旧评论创建接口。

每根评论最多一条作者答复，不支持读者互相回复或回复的回复。Comment只读新增parent_id、reply_version、author_reply；author_reply只附一层。parent_id为空表示根评论；根reply_version为0，答复从1递增。JSON中的uint64按既有protobuf约定使用十进制字符串。

GET /v1/comments/{id}/author-reply为管理员读取根的既有答复，允许读取其待审状态，无答复返回404。PUT相同路径接收content及显式expected_reply_version；0表示首次创建，编辑须匹配当前版本，冲突409不覆盖。调用者必须具备当前数据库管理员角色，编辑者还须与原答复作者相同。其他管理员可以明确删除再新建，不能冒用原作者身份。普通评论提交不能指定parent_id、user_id、昵称或作者标签。

公开Web列表以根评论分页，根和答复均须具备公开资格。子答复不占根的分页位置或评论数。父评论被删除/隐藏，或文章不公开，不能单独暴露答复。删除子只删除该答复；删除根包括其答复，客户端应明确提示。

本地内容校验、自动审核和限流沿用现有规则。被拒编辑和基础设施故障不覆盖旧内容，客户端保留原稿；版本冲突不得自动以新版本重试。草稿按账号和根ID隔离，迟到响应不得清掉另一账号/后续新稿。

小程序不沿用Web附带的答复。父与子各自具备当前App、作者身份、存储昵称与正文的双场景pass和一致输入摘要后，才可嵌套公开。所有层级的动态Web头像均不进入mini投影。原根v1哈希字节保持兼容；新子摘要绑定父ID和回复版本。修改子正文/状态使其所有App检测代数递增并失效，清旧身份引用、输入摘要、trace、检测时间、lease和错误；旧回调不能复活旧证据，包括A→B→A。

删除须显式清父子检测记录，不依赖自引用外键级联。原创建幂等键只保留既有最小deleted tombstone；不保留正文、身份或trace，阻止已删创建请求同键重建。网络检测不占用SQL事务；并发操作使用一致锁顺序与版本条件。

本轮小程序只承接安全读取和本人已有fresh-code重检，不增加写作者答复入口；源码变化不等于审核中的0.1.1包已更新。测试只调用合成检测，正式微信请求或新包上传需要各自准确版本范围。
