# 正式小程序切换与身份保留

适用于已批准的[正式接入计划](../../plans/FORMAL-MINIPROGRAM-TRANSITION-2026-10.md)。本文件定义操作顺序，不构成生产、凭据、平台或发布授权。

## 准备门禁

1. 本地/CI 与 `scripts/test_wechat_identity.py` 实际通过；核对准确源码、镜像摘要、v16 迁移及回填工具一致。正式号与旧身份来源 AppID 分别验证，不根据项目配置猜测旧生产身份来源。
2. 正式 AppSecret 由管理员保存在不提交的私密文件；不要覆盖公众号或其他配置。`wechat` 段只针对小程序，启用需 `enabled: true`。代理不读取或展示值。
3. 确定停止写入窗口，核验 SQL、uploads、私密配置备份及恢复演练。准备明确的运行配置 `wechat.enabled: false`，同时阻断登录和绑定。
4. 获取绑定准确源码/镜像/主机/配置/期限/次数的授权，涵盖旧实例停止、新实例启动、v16迁移、显式回填、正式配置启用后重启及必要补偿关闭。Git 交付和发布另走各自门禁。

## 固定执行顺序

1. 记录并正常停止全部旧 backend 实例，排空在途请求，确认没有旧绑定写入者。旧后端没有 enabled 守卫，不能用新配置代替停止旧进程。其他服务保持原状，存在短暂后端不可用窗口。
2. 以微信关闭配置启动 v16 后端；启动自动执行迁移。确认 schema 16、dirty=false、后端健康；实际检查微信登录/绑定均拒绝，普通邮箱登录及内容读取仍正常。
3. 停写期间运行回填 dry-run，明确传入已验证的旧 AppID；无冲突才 apply。核对旧列不变、覆盖完整、重复执行幂等。失败保持微信关闭。若返回提交结果未知，先只读核验实际映射和旧列，不把错误当作已经回滚，不盲目重试写入。
4. 成对配置正式 AppID/Secret，启用后重启同一 v16 后端；检查实际 AppID。小程序项目、后端凭据、预览所属 AppID 必须一致。
5. 正式 request 域名为 `https://makerhao.cn`，不含 `/api/v1`；保持 urlCheck=true。核对实际隐私内容、评论/问答适用声明和类目。正式首登由用户在小程序用原网站账号密码绑定，随后再次登录；核对网站 UUID/角色/头像/内容与旧身份均保留。
6. 核验正式号真机阅读、筛选、搜索、收藏、AI 来源和登录后，分别处理开发版本上传、提审、发布。备案审核中不等于成功，正式发布前确认有效备案及当时平台门禁；不把预览或上传称作发布。

## 故障边界

v16 生效后保留支持该版本的后端与数据库。新后端健康但微信异常时，仅关闭微信或恢复已验证的旧 AppID 配置；旧身份通过回填表查找，正式新增关系也保留。

旧 v15 镜像缺少 v16 migration 源，不能作为默认回退。迁移 dirty 或新后端启动失败时，暂停受影响服务并停止自动操作，准备准确授权的向前修复。不得 down/force version 或覆盖恢复生产数据库掩盖问题；不得声称关闭微信能修复不能启动的后端。

保留现有 Compose 镜像固定与 override 链，不能仅使用旧全局 IMAGE_TAG 覆盖其他服务。平台旧版本回退只按当时可用能力及明确目标另行办理。
