# 作者回复发布与恢复

对应[契约](../../contracts/AUTHOR-REPLIES.md)与[S4计划](../../plans/SERIES-AUTHOR-REPLIES-2026-11.md)。此文件是重复操作边界，不记录一次性许可或生产凭据。

发布前固定经过PR/required CI的源码、原始OCI镜像摘要及准确授权。只替换指定前后端服务，保留各自完整Compose覆盖链、uploads挂载和现有私密配置；不使用latest识别版本，不重建数据库/缓存/搜索/代理/监控服务。

当前升级为19→20：comments新增可空parent_id、自引用RESTRICT外键、唯一parent索引与reply_version，旧根默认parent=NULL/version=0，不回填安全pass。先备份并验证数据库/uploads/config，记录旧行字段摘要、schema/dirty、容器ID与配置摘要。隔离MySQL必须验证19备份恢复再升级、旧字段保留、旧根默认值、并发创建/编辑/重检锁序/删除和旧消费者回归。迁移前若dirty或版本不符即停止；运行后重新验证20 clean、旧数据和非选择服务保持。

后端仍通过既有配置启动迁移，不变更审核开关或微信凭据。Web回复使用既有自动策略，小程序分别验证父子身份与双场景证据，不调用付费第三方审核。未检回复不能因Web公开或管理员批准进入mini。正式微信调用、测试写入和小程序新包不包含在普通服务部署中；需要时按准确范围另办。

升级到20后禁止直接启动不含20迁移源的19后端，不执行down或force清dirty。需要停止新入口时可回退前端入口并保持兼容20的后端；后端缺陷使用兼容20的修复版本前滚。任何数据库恢复、撤回发布或再次部署均按具体目标重新授权，不能用自动重试掩盖未知结果。

线上最小只读验收：系列目录/前后篇/站点地图；匿名评论列表仍按根分页、批准答复单层展示；管理接口匿名401/读者403；mini公开接口不泄露未检答复或动态头像；schema20 clean与旧记录/上传/配置保持。写入行为由隔离真实MySQL和本地浏览器验证，不为冒烟修改现有用户评论或冒充作者检查。

小程序0.1.1代码与隐私仍按用户最新反馈在审核。新源码不是已经上传的包；不得重复提审或将Web部署汇报为新小程序功能已正式发布。
